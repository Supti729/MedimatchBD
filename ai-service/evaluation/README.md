# Evaluation — how the model was chosen

Run it yourself:

```bash
HF_HOME=.hf-cache .venv/bin/python -m evaluation.evaluate
```

`results/report.md` and `results/results.json` are generated by that script and are not edited by hand.
This page is the human interpretation of the run committed with the project.

## Dataset

`dataset.json` — 33 listings of common Bangladeshi brands and 56 queries, written and labelled by hand:
brand names, generic names, natural sentences, pharmacy shorthand, misspellings, Bangla, strength-specific,
form-specific, and 6 medicines that are **not** in the corpus. A listing is relevant only when ingredient,
strength and form match what the query asks for. There are deliberately **no symptom queries**
("medicine for fever"): mapping symptoms to medicines would be medical advice, which the platform never gives.

## Findings (run of 2026-11-08)

| System | P@5 | R@5 | MRR | Hit@1 |
|---|---|---|---|---|
| Part 2 keyword search (all words must match) | 0.168 | 0.507 | 0.56 | 0.56 |
| BM25 keyword ranking | 0.34 | 0.96 | 0.878 | 0.84 |
| paraphrase-multilingual-MiniLM-L12-v2 + rules | 0.344 | 0.99 | 0.953 | 0.92 |
| **multilingual-e5-small + rules** | **0.344** | **0.99** | **0.99** | **0.98** |

1. **Semantic matching clearly beats keyword matching** on wording that differs from the catalogue:
   misspellings (MRR 1.0 vs 0.333 for the Part 2 search), Bangla (0.938 vs 0.0), natural sentences (1.0 vs 0.0) and shorthand.
2. **`intfloat/multilingual-e5-small` is selected.** It beat MiniLM in every category and especially on brand names and
   Bangla. It loads in about 6 s and embeds a query in about 11 ms on a laptop-class CPU.
3. **P@5 hardly separates the systems** because most queries have only 1–3 relevant listings (the best possible P@5 is 0.348).
   MRR and Hit@1 are the informative metrics here.
4. **Similarity alone is not a safe identity check.** e5 gives unrelated medicines high cosine values (e.g. `ibuprofen 400`
   reaches 0.856 against the closest listing). In the threshold study, 0.86 kept 44/50 correct answers with 0/6 false accepts,
   but on a set this small that number must not be trusted on its own. This is why Medimatch BD:
   - always applies the **hard rules first** (catalogue identity or exact strength + dosage form, eligibility, availability);
   - only uses AI-suggested identities when similarity ≥ 0.86 **and** strength and form match the request exactly, and
     labels them "suggested — check the medicine name";
   - never lets similarity override eligibility, verification or medical judgement.
5. The single failure was the Bangla brand name `সেকলো ২০` (Seclo 20), ranked behind another 20 mg acid-reducer.
   Bangla brand names transliterated phonetically remain the weakest case; adding Bangla aliases to the catalogue fixes it
   for keyword search too.

## Limitations

- Small, hand-made dataset (56 queries, one labeller). Results show a clear direction, not a precise production estimate.
- The thresholds were studied on the same data they are reported on; a larger, separate test set is needed before real use.
- Listing texts are clean catalogue descriptions; real user-written text would be noisier.
